# 企业知识生产文档类型管理设计

## 目标

为企业知识生产补齐文档类型配置入口，使租户管理员可以创建文档类型草稿、查看同一类型的版本状态并激活指定版本，从而解除项目工作台“当前没有启用中的文档类型”的阻塞。

## 范围

- 在知识生产项目列表页头部增加“文档类型管理”入口。
- 新增独立的文档类型管理页，列出当前租户的全部类型版本。
- 支持创建完整的文档类型草稿，字段与现有后端 API 保持一致。
- 支持激活草稿；后端负责将同 code 的旧生效版本转为 retired。
- `admin` 和 `owner` 可以创建、激活；`viewer` 和 `contributor` 只读。
- 不新增、修改或删除后端接口，不提供已生效版本的原地编辑。

## 页面与交互

页面沿用当前 TDesign 企业工作台的安静、紧凑风格。页头提供返回项目列表、刷新和创建草稿操作；主体使用表格展示名称、code、schema version、状态、描述、更新时间和操作。状态分别显示为草稿、生效、已退役。

创建操作使用右侧抽屉，基础字段为 code、名称、描述和 schema version；`block_schema`、`source_requirements`、`skill_bindings`、`workflow_plan`、`quality_rules`、`review_policy`、`publication_policy` 使用 JSON 文本域。所有 JSON 字段默认 `{}`，提交前在客户端解析并提示具体字段的格式错误。

激活草稿时显示二次确认，说明同 code 当前生效版本将被替换。激活中禁用重复操作；成功后刷新列表。生效或退役版本不显示可执行的激活操作。

## 权限与数据流

页面进入后调用 `GET /api/v1/production/document-types`。创建和激活分别复用现有带 `Idempotency-Key` 的前端 API。前端权限只用于可见性与禁用状态，后端 `Admin` 中间件仍是最终授权来源。

若加载失败，页面显示错误状态与重试操作；空列表展示面向当前权限的空状态。创建或激活失败时保留用户输入并展示服务端错误，不在失败后伪造本地成功状态。

## 验收标准

- 项目列表页可以进入 `/platform/knowledge-production/document-types`，且知识生产菜单保持激活。
- 所有租户角色均可查看文档类型列表。
- 只有 `admin/owner` 可以打开创建抽屉和确认激活。
- JSON 无效时请求不会发出，并指出出错字段。
- 创建后出现 draft 版本；激活后刷新并显示 active/retired 状态。
- 中文、英文、韩文和俄文均具备完整文案。
- 桌面端与移动端无页面级横向溢出，表格允许局部横向滚动。
